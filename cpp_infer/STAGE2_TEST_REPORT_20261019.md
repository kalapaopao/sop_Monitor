## 2. 实现和决策

### GPU RTMW：已实现

- 沿用现有人体框、1.25裁剪扩展和宽高比规则，CPU只计算2x3仿射矩阵。
- GPU按OpenCV的定点坐标与插值表执行裁剪、零边界填充和归一化。
- 保持原通道顺序、输入尺寸、归一化常量及SimCC解码方式。
- 原GPU原图由OBB与RTMW共享，RTMW不再单独上传CPU裁剪后的浮点输入。

### YUV直接进入GPU：原型已试验，未通过一致性

- 原型上传I420并在GPU转换到BGR，可将1080p源图H2D从6,220,800字节降至3,110,400字节。
- 但03第零帧的骨架偏移约8.504 px，超过事先设置的3 px阈值。
- 此样例框角点差异小于1 px，置信度差约0.0015，仍不能替代骨架核对。
- GPU转色对CPU参考的首样例像素MAE约1.45908、最大通道差3，但仍引起上述关键点变化。
- 没有降低阈值，也没有宣称该路径保持效果。运行入口提前拒绝 `--source-layout i420`，
  只保留 `stage2_test ... --i420` 诊断。该失败后其余YUV样本未继续运行。
- 成功路径仍使用已核对的CPU颜色转换。共享GPU原图已减少RTMW张量的重复上传，
  但不等于实现零拷贝，也没有取消CPU预览颜色转换。

### 缓冲区和同步：已实现可选复用

- 每个实例独立保留锁页源图/输入/输出、结果数组和完成事件。
- 固定输出形状的容器只在首次或增大时分配；只读引用避免返回结果时的额外容器拷贝。
- GPU裁剪后无需构造CPU裁剪图/归一化浮点向量。
- CPU旋转NMS需要检测输出，RTMW人体框依赖NMS，因此保留必要的GPU完成等待。
  完成事件用于等待已排队的读回完成，没有把“改成事件”描述成消除了同步。
- 复用范围是模型I/O，不是整个视频程序逐帧零分配；解码帧和检测结果仍有常规分配。

## 3. 一致性检查与失败处理

- 数值测试覆盖非连续行跨度、随机图、越界人体框、部分出界框及小数坐标。
- 最初使用float归一化，张量最大差约2.38419e-7，但真实RTMW可见关键点差约6.01355 px，
  分数差约0.00244141，未通过模型阈值。
- 对齐CPU双精度常量/运算后再转float，修正了该误差，没有修改模型、阈值或置信度策略。
- 修正后的FP32数值与CPU参考一致；FP16测试保留其量化舍入容差。
- 03、07各第0/30/60帧共六组，检测框/置信度、可见关键点/分数与CPU参考一致。
  关键点几何比较以当前显示阈值0.35为界；这不是标注数据上的准确率评估。
- YUV失败单独保留日志，不将它包含在通过的BGR模型检查里。
- 原联合模型TensorRT/ONNX的历史个别置信度差异没有在本轮解决。

## 4. 性能方法与实测

比较相同权重、相同四路输入的前30秒，前5秒作为预热。先无窗口，再四宫格。
一个推理工作线程；没有与编译/其他推理检查同时测量。系统桌面、RDP和既有后台服务保持。
既有 `sop_nx_accel_probe` 为基线，新入口 `sop_nx_stage2_probe` 分别测开关。

- control：CPU RTMW，复用关闭。
- reuse_only：CPU RTMW，复用开启。
- warp_only：GPU RTMW，复用关闭。
- warp_reuse：GPU RTMW，复用开启。

新任务Hz、四宫格呈现FPS和结果年龄分别记录。结果年龄来自文件帧号/源帧率，
不是摄像头端到端时延。系统RAM包括桌面等服务，不能当作当前进程的独占GPU内存。
采用顺序短时对照，没有多轮随机顺序统计，不代表硬件最高帧率。
