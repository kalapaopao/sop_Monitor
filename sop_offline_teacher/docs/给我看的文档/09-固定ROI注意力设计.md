# 09 · 固定 ROI「注意力引导」设计（不是裁剪）

> 读者：项目负责人。已实现部分与未实现部分分开标注。

## 一、先把你的要求复述准确

你要的是：

> 用户画几个固定矩形，模型**更关注**这些区域，但**不是只看**这些区域。

技术上这对应「**空间注意力引导**（attention guidance）」，而不是「裁剪（crop）」。
两者差别很大：

| | 裁剪 | 注意力引导 |
|---|---|---|
| 模型看到 | 只有框内像素 | 全画面 + 框内被强化/额外编码 |
| 全局信息 | **丢失**（人在哪、有没有走过来、手出画了没） | 保留 |
| 换产线 | 框画错＝直接看不见 | 框画错只是"权重给偏了"，仍有兜底 |
| 实现 | 一次 resize | 需要多路输入或权重图 |

**我选注意力引导，理由如下。**

## 二、我为什么不做"乘一个软遮罩"

最便宜的做法是：全图乘一张权重图（框内 1.0、框外 0.3）再送入网络。实测经验里这条路在 CNN 上收益很小，原因有二：

1. CNN 的卷积核本来就在学"哪里重要"，人为压暗框外往往只是把像素值改小，网络学一个缩放就能抵消；
2. 压暗会破坏颜色/纹理统计，反而可能伤害性能（框外恰好有工具或工件的时候）。

**所以我用「双通路（dual-path）」：全局低分辨率 + 区域高分辨率，两者拼接。**
这样"关注"是靠**给区域一路更清晰的输入**实现的，而不是靠把别处压暗。

## 三、推荐的输入结构

```text
同一个源帧
   │
   ├─ 全局缩略图 224×224 ─────────────→ 编码器 → 全局特征（保住"整体在发生什么"）
   │
   ├─ 左手周 ROI 128×128 ─────────┐
   ├─ 右手周 ROI 128×128 ─────────┼→ 共享编码器 → 各 576 维外观特征
   ├─ 固定区 A（装配区）128×128 ───┤
   └─ 固定区 B（承接面）128×128 ───┘
                                    │
   骨架 50 点 + 手部几何 + 区域状态量 ─┤
                                    ↓
                       拼接成每 tick 的特征向量
                                    ↓
                        历史窗口 → 因果 TCN → 工序/左右手
```

关键点：

- **固定区是"额外一路"，不是"唯一一路"**。全局 224 那路永远存在，这就是"不是只看这个区域"的保证。
- 编码器**共享权重**，四个区域 + 全局一起批处理，不重复开模型。
- 每个区域带 **valid 标志**：没裁到就置 0 并标记缺失，**不能**把黑图当真实观测。

## 四、成本实测（CPU，4 线程）

`MobileNetV3-Small` 128×128 单张 **3.56 ms**：

| 场景 | 每秒编码张数 | 估算占用 |
|---|---|---|
| 单路 3 区域 @10Hz | 30 | **0.11 核** |
| 4 路 3 区域 @10Hz | 120 | **0.43 核** |

→ 注意力引导本身**几乎不增加算力负担**，成本主要在 YOLO+RTMW（实测 25.6 ms/帧）。

## 五、数据契约：`configs/stations.json`

```jsonc
{
  "version": 1,
  "stations": [{
    "id": "ST01",
    "name": "默认工位",
    "frame": [1920, 1080],          // 画框时的画面尺寸，仅作参考
    "regions": [{
      "id": "rmwglnklx",
      "name": "装配区",
      "type": "focus",               // focus=注意力引导 | state=状态判定
      "rect_norm": [0.42, 0.55, 0.68, 0.88],  // 归一化坐标，分辨率无关
      "color": "#7bd6be",
      "enabled": true
    }]
  }]
}
```

为什么用**归一化坐标**：换分辨率、换导出尺寸都不用重画；机位不变就能复用。

## 六、两种区域类型

| type | 用途 | 额外产出 |
|---|---|---|
| `focus` | 让模型重点看 | 裁图 → 编码特征 |
| `state` | 判断"件放上去没有" | 裁图 + **变化强度**（与参考帧逐像素差分均值） |

`state` 的"变化强度"是**可解释、可验证**的量：数值跳变通常对应"放上去/拿走"。
实测当前两个区域：变化强度中位 8.03、最大 92.09（数值范围 0–255）。

## 九、需要你确认

1. **区域数量**：一般 2~4 个够（装配区 + 承接面）；你要不要更多？
2. **`state` 区域的参考帧**：目前用第一帧。更稳的做法是"该工位空载时的帧"，需要你确认哪一帧是空载。
3. **全局那一路的分辨率**：我建议 224×224（够看整体，成本低）。
