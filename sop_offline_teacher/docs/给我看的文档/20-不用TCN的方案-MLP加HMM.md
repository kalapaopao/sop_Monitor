# 20 · 不用 TCN 的方案：逐帧 MLP + HMM 状态机（88.6%，反而更好）

> 背景：用户明确要求不使用 TCN（父项目里"骨架 + 检测 + 状态机 + TCN"试过没做成）。
> 本文记录去掉 TCN 后的三条替代路线实测，结论是 **MLP + HMM 比 TCN 更好**。

---

## 一、四条路线对比（全部 7 周期留一、无泄漏、同 v3 特征 153 维）

| 路线 | 是否含可训练时序网络 | **帧级准确率** | 段级 F1 |
|---|---|---|---|
| **MLP + HMM 解码** | ❌ 无（逐帧 MLP + 转移矩阵 + Viterbi） | **88.6%** | **0.43** |
| TCN（窗口 15 帧） | ✅ 有 | 85.5% | 0.39 |
| MLP 逐帧（无时序） | ❌ 无 | 84.4% | — |
| HMM（高斯发射） | ❌ 无 | 36.1% | — |

**关键结论：MLP + HMM 用"最笨的逐帧分类器 + 一个状态机"打败了 TCN。**

---

## 二、MLP + HMM 具体是什么

```text
① 逐帧 MLP（只看当前帧的 153 维特征）→ 输出 7 类概率
        ↓
② 转移矩阵（从训练周期的 GT 序列统计，可人工查看/手改）
        ↓
③ Viterbi 解码（求整条序列的最优路径）
        ↓
④ 后处理状态机（确认切换 / 最短段长 / 合并）
```

**没有任何卷积循环网络、没有窗口采样、没有训练时的时间维度。**

### 为什么它比 TCN 好

| 原因 | 说明 |
|---|---|
| 参数更少、更不易过拟合 | MLP 只看当前帧，泛化到未见周期更稳（c0 从 TCN 的 63% → 4 个点以上） |
| 时序约束更"硬" | Viterbi 用全局最优路径，而 TCN 是局部窗口投票，长动作边界更稳 |
| 转移矩阵可解释、可手改 | 业务上可以直接改"哪些步骤不能相邻"，TCN 做不到 |
| 不依赖窗口长度超参 | TCN 的 win=15 是个需要调的参数 |

## 五、关于"你们以前试过 TCN 没做成"

我理解你的顾虑，但需要区分两件事：

| | 父项目旧任务 | 本项目任务 |
|---|---|---|
| 标签 | 二分类「是否在用螺丝批」 | 多分类「当前是哪个 SOP 步骤」 |
| 标签问题 | 含持有/移动/停顿，与"是否拧紧"不一致 | GT 是人工工序边界，语义干净 |
| 输入 | 手框 + 骨架 | 骨架 + 身体点 + 手部几何（153 维） |
| 结果 | 未成立 | TCN 85.5%，MLP+HMM **88.6%** |

**旧结论成立的原因很可能是标签语义错位**（Codex 也独立得出同样判断），不是"时序模型不行"。
不过既然现在 MLP+HMM 更好，**用哪条都不影响结论——我们不需要 TCN 了**。
