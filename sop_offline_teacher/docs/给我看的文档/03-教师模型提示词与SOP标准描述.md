# 03 · 教师模型提示词与 SOP 标准描述

> 读者：项目负责人。本文是**可执行的草案**，SOP 步骤表需要你审核后冻结。

## 一、现在的提示词（`api_teacher/run_ablation.py`）

```text
你是工业现场动作分析教师模型。根据连续画面和可用证据，自由命名当前最具体的动作。
分别描述 action、phase、left_hand、right_hand、tool、object、relation、change、unknown。
只写画面或证据直接支持的内容，无法确认写 unknown。只输出 JSON。
```

**问题清单：**

| 问题 | 后果 |
|---|---|
| "自由命名" | 每次措辞不同，无法统计、无法验收 |
| 没给候选步骤 | 模型会"发明"动作，和 SOP 对不上 |
| 没强制语言 | A 组输出中文、B/C 组输出英文 |
| 没约束长度 | 有的字段写成整句，卡片排版崩 |
| 没给时间上下文 | 模型不知道"上一个窗口做了什么"，`change` 字段经常空 |

## 二、字段对照：我们 vs 参考视频

| 参考视频卡片 | 我们的字段 | 状态 |
|---|---|---|
| 标准 SOP 描述（工序 + 目标） | `phase` + `object` | ⚠️ 字段够，但没有 SOP 表可对齐 |
| 当前动作描述 | `action` + `change` | ✅ 够 |
| 左手（动作 / 器件） | `left_hand` + `tool` | ⚠️ 没有"左手拿了什么"的独立字段 |
| 右手（动作 / 关系） | `right_hand` + `relation` | ⚠️ 同上 |

**建议新增字段**（让左右手各自带"拿着什么"）：

```jsonc
{
  "step_id": "S08",              // 命中 SOP 表的哪一步
  "step_name": "黑色手持器朝向工件表面",
  "sop_expect": "右手把黑色手持器朝向工件表面，左手扶住装件",
  "action": "工具朝向工件",
  "left_hand":  { "action": "扶住", "holding": "装件", "target": "夹具内工件" },
  "right_hand": { "action": "朝向", "holding": "黑色手持器", "target": "工件表面" },
  "relation": "右手工具作用于左手固定的工件",
  "change": "工具由取料位移到工件表面",
  "unknown": ""
}
```

## 三、SOP 标准描述表（✅ 已拿到原图文字，见 `05` 文档；⚠️ 待你核对错字后冻结）

> ⚠️ **重要更正**：上一版本里写的「放镜 / 放镜框 / 装 NFC / 打螺丝 / 扫码 / 标记 / 合盖」
> **是错的**——那是我从别的项目记忆里搬来的八类动作，**不是这个参考视频的内容**。
> 已用 Windows 本地 OCR 从你发的截图里提取出真实文字，完整证据在
> [`05-参考视频SOP描述OCR记录.md`](05-参考视频SOP描述OCR记录.md)。

参考视频里实际是 **11 条「标准 SOP 描述」（其中 1 条重复，去重后 10 条）**：

| step_id | 标准 SOP 描述（OCR 整理版） | 类型 |
|---|---|---|
| S01 | 取得黑色壳片并与银灰件靠合 | 取料 + 装配 |
| S02 | 圆环状部位处理并暂放装件 | 局部处理 |
| S03 | 取得带线壳体并落座夹具 | 取料 + 定位 |
| S04 | 装件与壳体汇合及线状部位整理 | 组合 + 理线 |
| S05 | 夹具内供小件与悬挂工具作业 | 工具作业（OCR 错字最多，待确认） |
| S06 | 组合件移出并放到后方承接面 | 出料 |
| S07 | 取得本次银灰带筋件并建立持握 | 取料 + 持握 |
| S08 | 黑色手持器朝向工件表面 | 工具朝向 |
| S09 | （与 S07 重复）取得本次银灰带筋件并建立持握 | 循环重复 |
| S10 | 流程外或插入式局部处理 | **异常/兜底** |
| S11 | 循环外停留与准备 | **循环边界** |

**需要你确认的点：**

1. **同工位吗？** 这批物件（黑色壳片、银灰件、带线壳体、银灰带筋件、黑色手持器、后方承接面）
   与我们 `v2_5m_7m_h264.mp4` 里的（黑色塑料外壳、电动螺丝刀、孔位）**是否是同一套产品**。
   若不是，照抄会让教师模型把动作硬套到不存在的物件上——这是最关键的一个问题。
2. 第 5 条「夹具内供小件与悬挂工具作业」是 OCR 错字最多的一条，请对照原图确认。
3. 顺序对不对？截图是"来来回回"记录的，未必是工艺时序。
4. 每步的**目标物**叫什么（卡片上要显示）。
5. S10 / S11 这类"非作业"兜底要不要保留（我建议保留，它让时间轴能铺满全片）。

## 四、建议的新提示词（草案）

```text
你是工业装配现场的 SOP 动作分析教师。你会看到同一个工位的连续画面
（按时间顺序）以及可用的结构化证据。

请把当前窗口归类到下面 SOP 步骤表中的某一步，并描述左右手各自在做什么：

SOP 步骤表（OCR 提取的参考视频原文，待你确认同工位后冻结）：
S01 取得黑色壳片并与银灰件靠合｜S02 圆环状部位处理并暂放装件｜
S03 取得带线壳体并落座夹具｜S04 装件与壳体汇合及线状部位整理｜
S05 夹具内供小件与悬挂工具作业｜S06 组合件移出并放到后方承接面｜
S07 取得本次银灰带筋件并建立持握｜S08 黑色手持器朝向工件表面｜
S10 流程外或插入式局部处理｜S11 循环外停留与准备｜
S00 其他/过渡（不属于以上任何一步）

规则：
1. step_id 必须从上面选一个，禁止自创。
2. 若画面处于两步之间的过渡（伸手、等待、离开），选 S00；
   非作业停留选 S11，插入式局部处理选 S10。
3. 只描述画面或证据直接支持的内容；看不清就填 "unknown"，不要推测。
4. 全部字段用简体中文，每个字段不超过 20 个字。
5. 只输出 JSON，不要解释、不要 Markdown 代码块。

输出格式：
{
  "step_id": "S08",
  "step_name": "黑色手持器朝向工件表面",
  "action": "当前最具体的动作",
  "left_hand":  {"action": "左手在做什么", "holding": "左手拿着什么", "target": "作用于什么"},
  "right_hand": {"action": "右手在做什么", "holding": "右手拿着什么", "target": "作用于什么"},
  "relation": "两只手与工具、工件的组合关系",
  "change": "相比上一个窗口发生了什么变化",
  "unknown": "无法确认的内容，可为空"
}

结构化证据：{evidence}
```

改完立刻能看到的两个改善：**语言统一**、**卡片内容可统计**。

## 五、证据注入怎么做（A/B/C 三组的结论怎么用）

现在 `run_ablation.py` 的三组：

| 组 | 注入内容 |
|---|---|
| A | 无 |
| B | `frames` / `person_frames` / `person_present` |
| C | B + `hand_detections` + `left_wrist` / `right_wrist` 坐标 + `hand_keypoints_available` |

**建议的 D 组（下一步该做的）**：注入**左右手是否持有物体 + 手持物体类别**，
这才是区分"左手扶 / 右手拧"的关键证据。没有任何目标检测时，退一步用：
手腕速度、两腕距离、腕到工件中心距离。

## 六、成本估算（不写单价，只给公式，费用以百炼控制台为准）

```text
调用次数 = ceil(视频时长 / stride)
图片总数 = 调用次数 × frames
```

| 场景 | 时长 | stride | frames | 调用次数 | 图片数 |
|---|---|---|---|---|---|
| 现在的试点 | 30 s | 3 s | 3 | 10 | 30 |
| 120 s 片段 | 120 s | 3 s | 3 | 40 | 120 |
| 120 s 细粒度 | 120 s | 1 s | 3 | 120 | 360 |
| 参考视频全长 | 599 s | 3 s | 3 | 200 | 600 |
| 参考视频细粒度 | 599 s | 1 s | 3 | 599 | 1797 |

**建议**：先用 `120 s / stride 3`（40 次调用）验收卡片质量，
再加密度。不要一上来就全片 stride 1。
