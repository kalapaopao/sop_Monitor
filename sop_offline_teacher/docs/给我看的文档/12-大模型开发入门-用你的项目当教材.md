# 12 · 大模型开发入门（用你的项目当教材）

> 读者：项目负责人（想入门大模型开发）。
> 教材：本仓库真实踩过的坑 + 真实实测数字。不是抽象概念。

---

## 一、先纠正一个最大的误区：**你不一定需要"微调"**

很多人说"要让模型按我的要求输出，得微调"。**这句话在 90% 的工业场景里是错的。**

控制大模型输出有 5 层手段，从轻到重：

| 层 | 手段 | 成本 | 能解决什么 | 你现在做了吗 |
|---|---|---|---|---|
| L1 | **提示词工程**（角色/任务/判据） | 0 | 输出跑偏、语言漂移 | ⚠️ 做了但不完整 |
| L2 | **结构化输出约束**（JSON schema） | 0 | 字段缺失、格式乱、无法程序处理 | ✅ 已做 |
| L3 | **词表/白名单**（限定可选值） | 0 | 编造不存在的物体（幻觉） | ❌ **没做，这是最大漏洞** |
| L4 | **后处理与校验**（parse + retry + schema 校验） | 0 | 偶发脏输出、中文漂移 | ✅ 已做 |
| L5 | **证据注入**（多图/坐标/裁剪图） | 低 | "信息不足"导致的误判 | ⚠️ 已实现未验证 |
| L6 | **微调**（SFT / LoRA） | **高**（要几百~几千条标注对 + 训练资源） | 风格/术语/格式**极度固定**且调用量巨大 | ❌ 且**当前不该做** |
| L7 | 蒸馏 / 换更小模型 | 中 | 降延迟降成本 | ❌ 这是学生模型的事 |

**结论：你的项目现在该补的是 L3 和 L1（改问法），不是 L6。**

## 二、用你的项目逐层演示"控制"

### L1 · 提示词：先明确"回答什么、不许做什么"

**你现在的提示词（自由发挥版）**

```text
请回答：这段时间里操作者在做什么？
1. action：一句话描述（不超过 30 字）…
2. phase_key：稳定的短标识…
```

**问题**：没说"不许编造没看见的东西"，也没说"如果分不清要写什么"。
结果就出现了幻觉：`扫码枪`、`塑料袋`、`线束`、`电机外壳`（工位里根本没有这些）。

**改法（关键三句）**

```text
【只能写画面里真实出现的东西】
- 可用物件白名单：镜座组件 / 镜座上盖 / 镜子镜座 / 镜座扎带 / 镜座密封塞 / 螺丝刀 / 夹具 / 手
- 若画面里出现白名单以外的物体 → 写「未识别物件」，禁止猜名字
- 若看不清动作 → state_change 填 none，action 写「无法确认」
【禁止同义词替换】不要把「镜座」写成「外壳/电机壳/盖板」
【判断依据要落在可视证据上】写 action 时必须能指出：手的动作 + 物件状态
```

### L2 · 结构化输出：让程序能可靠解析

你现在已经是 JSON，但不够严格。真正稳的写法是**给出 schema + 一个合法样例 + 明说"只输出这个 JSON"**：

```json
{
  "phase_key": "lower_snake_case",
  "action": "中文一句话",
  "state_change": "inserted | removed | fastened | none",
  "left_hand": "中文 ≤15 字",
  "right_hand": "中文 ≤15 字",
  "evidence_i_used": "你依据画面里哪一处判断的（中文 ≤20 字）",
  "confidence": 0.0
}
```

> 加 `evidence_i_used` 这个字段很重要：**它强迫模型说出依据**，编造时更容易暴露。
> 这是"让幻觉可见"的最便宜手段。

### L3 · 词表/白名单：掐死幻觉（你现在缺的核心手段）

**原理**：开放生成 → 模型会挑"最像装配的词"；给封闭词表 → 它只能在有限集合里选。

**两种强度**：

| 方式 | 做法 | 强度 |
|---|---|---|
| 软约束 | 提示词里列白名单 + "禁止自创" | 中（仍可能违规，需要校验） |
| 硬约束 | 枚举 + 程序校验，非法值直接重试或置空 | 高 |

你的场景建议**两者都上**：
1. 提示词给白名单；
2. 代码里校验 `action` 涉及的物件是否在白名单里，不在就标记 `need_review=true`（不假装成功）。

### L4 · 后处理与校验：不信任模型，也不放弃它

一条标准的"三明治"流程：

```text
组装输入 → 调模型 → 解析 JSON
                       ├─ 解析失败 → 重试 1 次（附"上次格式不对"提示）
                       ├─ 字段越界（如 state_change 不在枚举内）→ 归一到默认值 + 记 bad=true
                       ├─ 语言不对（无中文）→ 重试 1 次（附中文硬要求）
                       └─ 业务校验（物件不在白名单）→ 标 need_review
→ 写盘：raw（原文）、parsed（结构化）、flags（质量标记）
```

**关键原则：三条信息都要存**。只存 parsed 会让你永远不知道模型有多不可靠；
只存 raw 又没法统计。你项目里 `windows_freeform.json` 已经是这个思路（含 `raw`、`lang_bad`）。

### L5 · 证据注入：把"看不见"变成"看得见"

你已经在做（`clean / overlay / multi` 三种输入）。这里只提醒一条**判断标准**：

| 现象 | 说明 |
|---|---|
| 加证据后 IoU/边界召回明显上升 | 证据有效，加大投入 |
| 上升不明显 | 模型主要在靠场景先验，证据可省（省钱） |
| **下降** | 证据是干扰（比如烧在画面上的骨架线挡住了零件） |

**没有对比实验，就没有资格说"加骨架会更好"。** 这也是我给你做三种模式的原因。

### L6 · 微调：什么时候才真的需要

**微调（SFT / LoRA）解决的是**："模型完全知道该怎么做，但就是不肯用我的格式/术语"。

**它解决不了**：
- 画面里信息不足（装上盖 2 帧看不出"放上去"）→ 这是**输入问题**，微调救不了
- 需要精确时间边界 → 这是**任务形式问题**，改问法更有效
- 幻觉 → 词表约束比微调便宜得多

**什么时候值得微调**（满足 3 条以上再考虑）：

1. 任务固定、格式固定，**每天要调用上万次**（微调小模型更省钱）；
2. 有 **200~500 条以上**高质量"输入→正确输出"对（你现在只有 38 段标注，远不够）；
3. 提示词已经做到极致，仍有 10~20% 的格式/术语不达标；
4. 需要私有术语体系，且公开模型完全不懂；
5. 有训练资源（LoRA 至少一张 24G 显卡或租云）。

## 三、最重要的一条认知：**微调大模型 ≠ 得到能上设备的模型**

这是你路线里最容易混的一点：

```
微调后的 Qwen-VL  →  仍是几十亿参数，仍需联网/GPU，仍上不了 NX 多路
学生模型（TCN）   →  3M 参数，5~10 MB，能上 NX
```

**大模型在你项目里的角色是"标注入工具"，不是"部署模型"。**
所以"微调大模型"的优先级，**低于**"攒数据训学生模型"。

## 四、把"调参旋钮"认全（这些比微调常用 100 倍）

| 旋钮 | 你的场景建议 | 说明 |
|---|---|---|
| `temperature` | **0** | 分类/结构化任务必须 0，否则同样输入结果会变 |
| `top_p` | 1.0（不用动） | 与 temperature 二选一调整即可 |
| `max_tokens` | 小（200~400） | 输出短，省钱且减少跑偏 |
| `seed`（若支持） | 固定 | 便于复现；**需查 API 文档确认是否支持** |
| `response_format` / JSON mode（若支持） | 开启 | 比"提示词要求 JSON"更可靠；**需查文档确认** |
| 重试次数 | 1~2 次 | 再多不如改提示词 |
| 每次请求的图数 | 2~6 张 | 太多会稀释注意力（你 multi 模式 6 张） |

> ⚠️ 我**没有核实** Qwen-VL 这套 API 是否支持 `response_format` / `seed` / 函数调用。
> 这三项需要你或接手的人查阿里云百炼文档确认，不要按我这句直接写代码。

## 五、你现在这套提示词，我给出"可控版"

```text
你是工业装配现场的 SOP 动作教师。下面按时间先后给出同一工位的 {n} 张画面，
覆盖视频的 {start:.1f}–{end:.1f} 秒。

【可用物件白名单】（只能使用这些名词，禁止自创同义词）
镜座组件 / 镜座上盖 / 镜子镜座 / 镜座扎带 / 镜座密封塞 / 螺丝刀 / 夹具 / 手
若画面里出现白名单以外的物体，写「未识别物件」，不要猜名字。

【任务】
在这段画面里切分动作：如果中途换了动作，给出每个动作的起止秒数；
如果整段都是同一个动作，只给一段。

【判断要求】
1. action：中文，≤30 字，必须能对应到「手的动作 + 物件状态」。
2. state_change：只能取 inserted / removed / fastened / none。
   只有**物件状态真的改变**（装上了/取走了/拧紧完成）才填前三者，否则 none。
3. evidence_i_used：写出你依据画面里的哪一处判断（≤20 字）。
   如果找不到依据，action 写「无法确认」，confidence 填 0。
4. left_hand / right_hand：中文 ≤15 字；看不到写「未看到」。
5. 只输出 JSON，不要解释，不要 Markdown 代码块。

【输出格式】
{"segments":[
  {"start": 12.0, "end": 18.4, "action":"中文一句话","state_change":"none",
   "evidence_i_used":"中文","left_hand":"中文","right_hand":"中文","confidence":0.8}
]}
```

**改了什么、为什么**：

| 加的内容 | 解决你哪个已暴露的问题 |
|---|---|
| 物件白名单 | 编造"扫码枪/塑料袋/线束" |
| "找不到依据就写无法确认 + confidence 0" | 判错时置信度 0.92 的过度自信 |
| **输出 segments 数组 + 起止秒** | 边界 100% 锁在 6 秒网格（不再"一窗一标签"） |
| `evidence_i_used` | 幻觉难以自查，逼它指出依据 |
| temperature 0 | 同输入同输出，可复现 |

## 六、三个练习（用你自己的数据，10 分钟一个）

**练习 1：验证"白名单"能掐掉幻觉（5 次调用）**
挑 3 个之前出现过幻觉的窗口（如 312–318s 的"扫码枪"），用新旧提示词各跑一次，
比较输出里是否还出现白名单外的名词。

**练习 2：验证"切分问法"能破网格锁（10 次调用）**
取 30 秒（如 330–360s，含 1 个扎带 + 1 个装盖 + 1 个装塞），一次给 20 帧，
看它给出的边界是否接近 GT（329.6/341.6/343.3/350.5/353.2/357.5）。

**练习 3：验证"证据有没有用"（20 次调用）**
`clean` vs `multi` 各跑一遍同一段，比较 `eval_boundaries.py` 的两个数：
边界召回、段级 IoU。

## 七、入门要学的 6 个概念（搜这些词就够）

| 名词 | 含义（一句话） |
|---|---|
| **Prompt Engineering** | 用自然语言约束模型行为，不改参数 |
| **Structured Output / JSON Mode** | 让输出能被程序可靠解析 |
| **Constrained Decoding / Grammar** | 解码时直接限制可选 token（比提示词硬） |
| **RAG（Retrieval-Augmented Generation）** | 先取资料再回答；你的"证据注入"就是它的变体 |
| **Hallucination** | 编造不存在的内容 |
| **SFT / LoRA** | 用少量标注对微调；LoRA 只训练低秩增量，省显存 |

---

## 八、一句话总结

> **先用"词表 + 结构 + 校验"把输出管住，再用"证据"把信息补足；
> 微调是最后手段，而且微调出来的大模型仍然上不了产线设备。**
