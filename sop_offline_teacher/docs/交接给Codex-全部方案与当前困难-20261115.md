## 3. 全部试过的方案（按时间顺序，含数字与失败原因）

### 方案 1 ｜固定 3 秒窗口 + 6 帧 + 自由 JSON（ablation A/B/C）

- 做法：0–30 s 按 3 秒切 10 窗，每窗 6 帧，一次调用输出 `phase/action/left_hand/right_hand/tool/object/relation/change`
- 结果：描述看起来合理，但**用词自造**（"黑色塑料壳体（疑似车灯组件）"），中英混排，边界=3 秒网格
- 为什么停：没有步骤表、没有校验、无法对齐 GT
- 遗留：`web/public/data/ablation_14_A.json`（**现已从页面上彻底删除引用**）

### 方案 2 ｜闭集 7 类分类（center 窗口，GT 中心 ±1 s）

- 做法：49 窗口 × 3 帧，只许从 6 步 + idle 里选
- 结果：**总体 0.408**；持续性动作 14/16 = 87.5%，**状态变化型 3/21 = 14.3%**，idle 3/12
- 逐类：紧固 F1 0.86、取镜座 0.89 召回但精确 0.38、**装上盖 0%**
- 置信度：判对中位 0.94、判错中位 0.92（**错的时候一样自信**）
- 失败原因：窗口取在"动作中部"，看不到"放上去"这个状态变化

### 方案 3 ｜state 窗口（向动作两端各扩 0.6 s）

- 结果：**更差 0.347**
- 根因：**帧跑出段外**——"装上盖 75.48–83.72"的首帧 75.081 其实属于"取上盖(74.76–75.36)"，
  等于拿别人的画面贴这个动作的标签（邻居污染只影响 2/37 窗，**主因是帧越界**）
- 结论：弃用

### 方案 4 ｜inside 窗口（严格段内取"首/中/末"三帧）

- 结果：0/37 帧越界（实现正确），但未做完整评估
- 价值：确立了"帧必须落在标签区间内"这条硬规则

### 方案 5 ｜自由分段（stride 6 s，模型输出 phase_key 再合并）

- 20 窗口 / 20 次调用，中文 20/20 达标
- 段数 17 vs GT 13；**边界召回 53.8%（±1.5 s）**、精确 41.2%、段级 IoU≥0.5 仅 5/13 = 38.5%
- **结构性问题：18 条边界 100% 落在 6 s 整数倍**（段长 {6.0s:15, 24.0s:1}）
  → 它没有在"找切换点"，只是给每个 6 s 窗口贴标签
- 幻觉：提出"扫码枪/塑料袋/线束"等 —— **后来经确认真实存在**，只是不属于 SOP（见 §4.4）

### 方案 6 ｜把自由描述映射到 step_id（关键词法）

- 只用整串别名：映射率 **11.8%**（因为模型说"外壳/盖板"，SOP 名写"镜座/上盖"）
- 改成「动词 + 物件」两维打分：映射率 **94.1%**（严格）/ 100%（宽松）
- **但与 GT 一致率仍只有 17.6%** —— 映射器只能忠实映射**错误的描述**
- 教训：**格式对齐 ≠ 识别能力**

### 方案 7 ｜方案 A：视觉端直接输出 step_id（六步三要素写进提示词）

- 提示词含：S1~S6 的"手/物件/工具"三要素 + 典型时长 + 兜底 idle/unknown + 物件白名单
- 输出新增 `step_id`，枚举校验失败自动重试
- 实测（330–360 s，1 次调用）：**5 段**，`step_id` 全部合法、0 重试、描述与步骤自洽
- 问题：边界整体偏 **3.5–5 秒**；S6「系扎带」被漏判
- 提交：`05777cc`

### 方案 8 ｜方案 C：顺序约束解码（Viterbi）

- 转移概率从 GT 统计，排除被评估区间避免作弊
- **我先误报过一次**"30.8% → 53.8%"，根因：转移统计漏了 `idle`（只统计有标注的段），
  解码器几乎不能输出 idle，把 6 s 窗口硬判成步骤，**碰巧**对上部分 GT 段
- 修正后实测：**gamma≤0.3 时 30.8% → 30.8%（无增益）**；gamma=0.5/0.8 时降到 15.4%/7.7%
- 结论：**当前数据条件下顺序约束无增益**，`--gamma` 默认改为 0
- 提交：`05777cc`（含更正说明）

### 方案 9 ｜per-segment：GT 边界 + 逐段只判一次

- 做法：段内取 3 帧，只要求判一个 step_id（不再要求同时切分）
- 实测：**2/11 = 18.2%**
  - 短段（<1 s）4 段：0/4（0.28–0.76 s 的段 3 帧几乎同一画面，客观不可判）
  - 长段（≥1 s）7 段：2/7
- **错误配对统计（最重要的产出）**：

```
取镜座 → 取上盖      2 次
取镜座/取上盖 → 无法判定  4 次
系扎带 → 装密封塞     1 次
装密封塞 → 装上盖     1 次
```

→ **所有错误都指向同一件事：分不清"手里那个东西"**，不是分不清动作
- 提交：`95b81e3`、`c44957a`、`df4216f`

### 方案 10 ｜multi 输入（全局画面 + 左右手放大图）

- 针对方案 9 的诊断，每段额外发左右手周围放大图（±0.6 s 就近回退）
- 成本：11 段 → clean 22 张图 / multi 44 张图，调用数都是 11
- **状态：已实现、假端点验证通过，真实效果未验证**（缺 API Key）
- 提交：`7ea77c8`、`5c68e24`

### 方案 11 ｜本地边界检测（10 Hz 骨架变化点，0 API 成本）

- 特征：左右手腕位置/速度、手部尺寸、两手间距；MAD 阈值 + 局部极大 + 最小间隔
- 实测（±2 s 容差）：**召回 69.6%、精确 59.3%、命中误差中位 0.53 秒**
- 对比：VLM 的边界偏差 3.5–5 秒 → **本地骨架的时间精度高一个量级**
- 提交：`df7c581`

### 方案 12 ｜无监督原型发现（0 标注、0 API）

- 做法：10 Hz 骨架 6 维特征（按人体高归一）→ 变化点切段 → 每段重采样 16 点 → 标准化 → k-means
- 实测纯度（只算 GT 有标注的段）：K=4 **57.1%**、K=6 **64.3%**、**K=8 78.6%**、K=10 71.4%
- **关键发现**：K=6 时"簇 4"把 81–102 s 的 **4 段"紧固"全部聚到一起**（纯运动特征、零标注）
- 同一实验也显示边界：`空闲×6`、`装上盖×2+取上盖×1+取镜座×1` 混在一起 —— 与 VLM 错误结构一致
- 提交：`39996e9`

## 4. 当前困难（用户原话）与技术诊断

> 用户原话：**"模型输出出来的结合不了 SOP 我想要的装配步骤，模型输出不了我想要的 SOP 装配步骤，
> 不知道怎么让教师模型能够输出。"**

拆成可验证的 4 条：

### 4.1 有 3 对步骤在"动作层面"几乎一样（最根本）

| 步骤对 | 区别在哪 | 只看动作能分吗 |
|---|---|---|
| S1 取镜座 vs S2 取上盖 | 手里物件大小 | ❌ |
| S3 装上盖 vs S4 装密封塞 | 物件形状 | ❌ |
| S5 紧固 vs S6 系扎带 | 工具 vs 扎带 | ❌ |

方案 9 的错误配对 8 次中有 7 次发生在这 3 对内部 → 强证据。
**推论：任何"只看全局画面 + 动作语义"的 VLM 方案都有硬上限。**

### 4.2 采样间隔与 GT 粒度不匹配

GT 段中位 2.36 秒；VLM 曾用 4.28 秒一帧 → 55% 的段看不见（§2 表）。

### 4.3 边界精度不够

VLM 3.5–5 秒误差；业务需要 ±0.5 秒级别。
本地骨架 0.53 秒可用，召回只有 69.6%（需继续调）。

### 4.4 SOP 表可能不全（**未决，必须由项目负责人确认**）

GT 的空隙（约 54 秒 / 120 秒）里，模型一直在描述具体动作：
「撕开塑料袋取出小零件」「将线束插入工件接口」「拿起扫码枪」「放在绿色传送带」。
两种可能：
- **① 这些是真实工序，只是没标** → SOP 表缺步骤，GT 不完整
- **② 这些是备料/辅助动作** → 模型把准备动作当成了工序，需要提示词明确排除

**这一条不确认，一致率的分母就永远是错的。**

### 4.5 用户已确认的两条约束（不要推翻）

- 顺序约束**已按要求取消**（config / 解码器 / 提示词三处，提交 `66babd9`）
- 旧 ablation 数据**已从页面彻底删除引用**（提交 `a060daf`），不要恢复

## 5. 新方案（建议作为主线）：原型聚类 → 人工命名 → 学生模型

```
P0 数据基建（✅ 已完成）
   10 Hz 骨架 + 手框 + 手周 ROI 2679 张 + 固定区 ROI 3600 张 + GT 38 段
      ↓
P1 无监督原型发现（✅ 雏形已跑通，0 成本）
   骨架运动特征 → 变化点切段 → 重采样 → k-means(K=8) → 8 个"动作原型"
   （实测纯度 78.6%；"紧固"4/4 自动聚成一簇）
      ↓
P2 人工给原型命名（一次劳动 ≈5 分钟）
   每簇取 2~3 张代表帧 → 人工贴 SOP 名（或 unknown）
   ← VLM 唯一仍需要的地方：每簇 1~3 次调用（约 10~24 次），不是每段一次
      ↓
P3 学生模型（真正能上 NX）
   输入：10 Hz 骨架（50 点）+ 手框几何 + 手周 ROI 特征（MobileNetV3-Small 冻结）
   模型：2 层 TCN → 帧级边界（0.1 s）、~3M 参数、量化 <5 MB、可多路
      ↓
P4 闭环
   三轨展示 + 卡片 + BORIS 导出（已有）+ 新增「周期完整性检查」
   （GT 有 7 个周期，每周期一般 5 步 → 漏做/顺序错比逐帧准确率更贴合业务）
```

**为什么这条能绕开 §4.1**：
原型由**运动模式**定义，紧固/装配/绕带的运动差异大（实测紧固 4/4 分开）；
真正分不开的 S1/S2 这些，交给 P3 的**手周 ROI 图像特征**（学生模型看得到手里是什么）。

**与现方案的对比**：

| 维度 | 现方案（VLM 逐段判） | 新方案 |
|---|---|---|
| 每次跑成本 | 11~27 次调用/分钟 | **0 次**（VLM 只在 P2 用 K 次） |
| 边界精度 | 4 s 级 | 帧级 0.1 s |
| 换产线 | 重调提示词重跑 | 重跑 P1 + 改名 K 个原型 |
| 能否上 NX | ❌ | ✅ |
| 人工负担 | 每段复核 | 只命名 K 个原型 |
