## 4. 三次实验与实测数字（本轮核心产出）

### 4.0 时间轴换算（很重要）

实测对齐：`v2_5m_7m_h264.mp4` = `v2.mp4` 的 **300–420 s**（帧差 3.3–6.0 灰度级；错开 1–4 s 时为 10–27）。

```
片段内时间 t  ⟷  v2.mp4 时间 300 + t    （±0.5 s）
```

**已有姿态/ROI/骨架成片覆盖的正是这 120 秒**，其中 GT 有 13 段（一个完整周期 + 5 个短段）。
另：`v2.mp4` 容器声明 606.30 s，但**实际只能 seek 到 599.12 s**（尾部 7 s 不可解码，已加自动探测）。

### 4.1 实验一：闭集分类（center 窗口）— `api_runs/teacher_eval_A`

49 窗口 / 147 张图 / 49 次调用，**证据档 = 无**（只发画面）。

| 指标 | 结果 |
|---|---|
| 总体准确率 | **0.408** |
| 剔除短段 | 0.463 ｜ 仅短段 0.125（n=8） |
| 持续性动作（紧固/系扎带/取镜座） | **14/16 = 87.5%** |
| 状态变化型（装上盖/装密封塞/取上盖） | **3/21 = 14.3%** |
| idle | 3/12 = 25% |

逐类：紧固 P0.75/R1.00/F1**0.86**；取镜座 P0.38/R0.89；取上盖 P0.50/R0.14；**装上盖 0/0/0**；装密封塞 P0.22/R0.29；系扎带 0。
**置信度不可信**：判对中位 0.94，判错中位 0.92，29 个错误里 22 个置信度 ≥0.9。

### 4.2 实验二：闭集分类（state 窗口）— `api_runs/teacher_eval_state`

**更差（0.347）**，原因已定位：窗口向两端各扩 0.6 s，导致帧跑出段外——
例如"装上盖 75.48–83.72"的首帧 75.081 实际属于"取上盖(74.76–75.36)"，
**等于拿别人的画面贴这个动作的标签**。邻居污染只影响 2/37 窗，主因是帧越界。

### 4.3 实验三：自由分段（clean 模式）— `api_runs/free_clean`

用户实际执行：`stride 6 s`，20 窗口 / 40 张图 / 20 次调用，**中文 20/20 达标（重试 0 次）**。

| 指标 | 结果 |
|---|---|
| 段数 | 模型 17 vs 人工 13 |
| 边界召回（±1.5 s） | **53.8%**（26 条命中 14） |
| 边界精确 | 41.2%（34 条命中 14） |
| 命中边界时间误差 | 中位 **0.93 s** |
| 段级 IoU ≥ 0.5 | **5/13 = 38.5%** |
| IoU 中位 | 0.39 |

对的部分：紧固 IoU **0.80**、组装上盖 0.71、装密封塞 0.51、系扎带 0.50。
错的部分：0.3–0.8 s 的短动作 IoU 全部 ≤0.13。

**两个结构性问题（比分数更重要）**：

1. **边界锁死在 stride 网格**：18 条边界 **100%** 落在 6 s 整数倍上；段长分布 `{6.0s: 15, 24.0s: 1, 5.97s: 1}`；
   17 段用了 **14 个不同 phase_key**（12 个只出现一次）→ **它没有在"找切换点"，只是给每个 6 s 窗口贴标签**。
2. **视觉幻觉**：模型提到但工位并不存在的物件 ——
   `扫码枪、塑料袋、线束、电机外壳、金属支架、内部金属件、灰色壳体、银色工件、黑色盖板`；
   真实物件只有：镜座组件 / 镜座上盖 / 镜子镜座 / 镜座扎带 / 镜座密封塞。
   例：GT 的"系扎带（329.6–341.6）"被它判成 `tighten_screws`。

## 5. 从三次实验得到的结论

| 能 | 不能 |
|---|---|
| 长动作（>10 s）分段与识别：紧固 IoU 0.80 | 0.3–0.8 s 的短动作（取上盖/取镜座）几乎全错 |
| 自由描述整段工序，中文稳定达标 | 主动找动作切换点（只会按 stride 网格切） |
| 生成可导入 BORIS 的候选标注 | 准确说出"手里拿的是什么物件"（会编造） |
| 输出置信度 | 置信度可用（判错时同样 0.9+） |

**结论：教师可以生成候选，但必须配 ①物件白名单 ②"切分+给切换秒数"的问法 ③裁剪图证据；最终部署仍要学生模型。**

## 9. 新对话必须知道的坑（除 `05-踩坑与注意事项.md` 外的补充）

1. **PowerShell 会吃掉反引号**：不要用 PowerShell 拼 JS/Python 代码字符串（模板字符串会被破坏、
   `>` 会被当重定向）。要改代码用 `edit`/`write` 工具，或写成 `.py` 文件再执行。
2. **改完姿态/ROI 必须重跑三件**：`run_local_pose.py` → `extract_roi.py` → `render_pose_video.py --boxes`，
   否则视频里的骨架、手框、网页时间轴三者不一致。
3. **Chrome/Edge 缓存**：`/api/stations` 曾因无缓存头导致"保存了但读到旧的"，已加 `no-store`；自测时仍建议 `Ctrl+F5`。
4. **GBK 控制台**：脚本里已对 stdout 做 `reconfigure(utf-8)`；新脚本要照做，否则 `⚠` 等字符会抛异常。
5. **`v2.mp4` 尾部不可解码**：任何抽帧脚本都要先探测可 seek 边界（`probe_seekable_end`）。
6. **`v2_5m_7m_h264.mp4` 的 fps 是 24.702 不是 25**：帧号换算一律用 `frames/duration`。
