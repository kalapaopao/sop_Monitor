## 1. 启动前端（最常用）

```powershell
cd web
npm install        # 首次
npm run dev        # → http://127.0.0.1:5173/
```

- 端口和地址**写死在 `vite.config.js`**：`host: '127.0.0.1', port: 5173, strictPort: true`。
  不要再用 `--host`/`--port` 覆盖，否则 `strictPort` 会直接报错退出。
- **为什么写死 127.0.0.1**：早期只监听 `::1`（IPv6 回环），`http://127.0.0.1:5173/` 会连接被拒，
  表现为"网站打不开"。详见 `05-踩坑与注意事项.md`。
- 调试参数：`http://127.0.0.1:5173/?t=45` 直接定位到第 45 秒。

验收：打开页面应看到视频在播（且画面上已有 L 青 / R 橙 骨架）、右侧 4 张卡片、
底部「工序」轨道 + 「左右手识别片段」条；点片段条任意位置视频跳转。

## 2. 重新提取手部关键点

```powershell
& .venv\Scripts\python.exe api_teacher\run_local_pose.py `
  --video vedio\v2_5m_7m_h264.mp4 `
  --person-model model\yolo\best.onnx `
  --pose-model model\rtmw_wholebody_256x192.onnx `
  --output web\public\data\local_pose_2min.json `
  --start 0 --duration 120 --rate 5
```

| 参数 | 说明 |
|---|---|
| `--start` / `--duration` | 分析区间，秒 |
| `--rate` | 采样频率，默认 5 Hz。600 帧 ≈ 90 秒（CPU） |
| `--pad` | 人体框外扩比例，默认 `0.1`，避免手贴框边被裁掉 |
| `--max-palm-ratio` | 掌骨长度 max/min 上限，默认 `5.0`；超过判为假检测（撒成星形）。传 `0` 关闭 |

输出结构见 `04-数据结构说明.md`。实测 600 帧结果：
`person` 有效 520 帧、左手 452 帧、右手 413 帧（启用掌骨过滤后）。

## 2.5 裁手部 ROI 并把显示框写回姿态数据

```powershell
& .venv\Scripts\python.exe api_teacher\extract_roi.py `
  --video vedio\v2_5m_7m_h264.mp4 `
  --pose web\public\data\local_pose_2min.json `
  --out web\public\data\roi --size 96 `
  --box-pad 0.32 --person-k 0.35 --hand-k 2.2 --write-boxes
```

| 参数 | 说明 |
|---|---|
| `--box-pad` | **手框**（画面上给人看的）外扩比例，默认 0.32 |
| `--person-k` | **上下文 ROI** 边长 = k × 人体框高度，默认 0.35（主尺度，稳定不抖） |
| `--hand-k` | ROI 边长**下限** = k × 平滑手部尺度，默认 2.2 |
| `--scale-window` | 手部尺度时间中值平滑窗口，默认 1.6 秒 |
| `--size` | 裁图边长，默认 96 |
| `--write-boxes` | 把 `left_box/right_box/left_roi/right_roi` 写进 `--pose` 指向的 JSON |

> **两个框，两个用途，别混用**：
> - 手框（实线）用**不剔离群点**的范围，保证框住整只手，只表示"手在哪"；
> - 上下文 ROI（虚线）才是模型裁图输入，要覆盖"手 + 手持工具/工件"，
>   尺度按人体高度算，并用时间中值平滑压住抖动。

实测：600 帧 **4.2 秒**，961 张 96×96 小图 ≈ 2.9 MB。
`web/public/data/roi/` 已被 `.gitignore` 排除（可随时重算）。

## 3. 重新渲染带骨架的视频

```powershell
& .venv\Scripts\python.exe api_teacher\render_pose_video.py `
  --video vedio\v2_5m_7m_h264.mp4 `
  --pose web\public\data\local_pose_2min.json `
  --output web\public\video\v2_5m_7m_pose.mp4 `
  --boxes `
  --ffmpeg .ffmpeg\ffmpeg-9.0.2-essentials_build\bin\ffmpeg.exe
```

`--boxes` 会把左右手框也画进画面。**注意：网页不再自己画框**，
所有视觉元素（骨架 + 手框 + L/R 标签）都在这一个 mp4 里，所以改框大小必须重渲染（约 2 分钟）。

| 参数 | 说明 |
|---|---|
| `--crf` | x264 质量，默认 20；调小体积可传 23~26 |
| `--start` / `--duration` | 只渲染部分区间（秒），`--duration 0` = 到结尾 |

实测输出：2964 帧 / 119.99 s / 1920×1080 / 约 66 MB，手部绘制 4748 次。

> ⚠️ **改了 `run_local_pose.py` 的坐标逻辑，必须同时重跑第 2、第 3 步**，
> 否则网页上的骨架上视频（新的）与底部片段条（旧的）不一致。

## 4. Qwen-VL 三组消融（要 API Key）

```powershell
$env:DASHSCOPE_API_KEY="你的 Key"
$env:DASHSCOPE_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"

& .venv\Scripts\python.exe api_teacher\run_ablation.py `
  vedio\v2_5m_7m_h264.mp4 `
  --observations <观测数据.jsonl.gz> `
  --output api_runs\ablation_14_A `
  --mode A --duration 30 --stride 3 --frames 3
```

- `--mode` 取 `A` / `B` / `C`，**一次只跑一组**（脚本刻意不并发，避免资源争抢）。
- `A`：只发画面；`B`：+ 人在场证据；`C`：+ 手部检测数与左右腕坐标。
- 结果写 `api_runs\<输出目录>\ablation_results.json`，并生成 `ablation_report.html`。
- 把结果拷到 `web/public/data/ablation_14_{A,B,C}.json` 才会在网页上看到。
- Key 只走环境变量，**不写入任何文件**。

## 7. 常见启动失败对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `127.0.0.1:5173` 连接被拒，`localhost` 能开 | Vite 只监听了 `::1` | 确认 `vite.config.js` 有 `host: '127.0.0.1'`；或直接改用 `localhost` |
| 端口被占，`strictPort` 报错 | 旧 dev server 没退 | 杀掉旧 node 进程后重启 |
| 页面视频黑屏 / 播放失败 | 浏览器不支持该编码 | 页面会回落到 30 张抽帧图；换 `*_pose.mp4`（已是 h264/yuv420p） |
| 骨架上没有手 | `local_pose_2min.json` 路径错或未生成 | 看浏览器控制台 fetch 报错 |
| 右侧卡片一直是"未知" | `ablation_14_*.json` 未加载 | 同上，或 JSON 结构不符 |
| 片段条全空 | `left_hand`/`right_hand` 字段全空 | 重跑第 2 步 |
