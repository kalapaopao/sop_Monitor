# 01 · 项目架构与数据链路

> 读者：接手代码的开发者。本文只写**代码里能验证的事实**。

## 一句话

离线跑一遍视觉模型（人体 + 手部关键点 + 大模型动作语义），把结果固化成静态文件，再用一个 Vue 单页做回放演示。
**前端不跑任何模型推理**，只读 `web/public/` 下的静态资源。

## 两条数据流的关键差别

| | 手部关键点链路 | 动作语义链路 |
|---|---|---|
| 是否联网 | 否，全本地 ONNX | 是，必须 `DASHSCOPE_API_KEY` |
| 时间覆盖 | 全片 0–119.99s，5 Hz，600 帧 | 仅 0–30s，10 个 3 秒窗口 |
| 产物 | `local_pose_2min.json` + 烧骨架视频 | `ablation_14_{A,B,C}.json` |
| 网页用途 | 视频画面上的骨架 + 底部片段条 | 右侧卡片 + 「工序」轨道 |
| 成本 | 一次性算力（约 90 s / 600 帧，CPU） | 按窗口计费，`stride` 越小越贵 |

> ⚠️ 两条链路的**时间基准不同**（120s vs 30s），这是当前 UI 上最容易被误读的地方，详见 `04-数据结构说明.md`。

## 关键设计决定（以及为什么）

1. **骨架烧进视频，而不是用 canvas 叠加**
   早期版本用 `<canvas>` 绝对定位盖在 `<video>` 上，需要自己做时间同步、DPR 缩放、尺寸重绘，还受 `timeupdate`（约 4 Hz）限制导致骨架抖。改成离线烧录后，骨架与画面同一帧，前端只剩播放。
   代价：换参数必须重新渲染视频（约 2 分钟）。

2. **姿态数据独立保存**
   虽然网页不直接画骨架了，`local_pose_2min.json` 仍然保留，因为：
   - 底部「左右手识别片段」进度条要按同样阈值切段；
   - 后续学生模型训练要用这些数值特征做输入。

3. **采样 5 Hz 而不是逐帧**
   25 fps 逐帧跑 RTMW 在 CPU 上过慢。5 Hz + 渲染时按相邻帧线性插值，视觉上连续。

4. **A/B/C 消融而不是直接上最终方案**
   目的是量化"给教师模型喂多少结构化证据才值得"。三组结果目前都只有 0–30s。

## 端口占用

| 端口 | 归属 | 说明 |
|---|---|---|
| 5173 | `web` 的 Vite dev server | 唯一入口，`npm run dev` |
| 8765 | `api_teacher/serve_dashboard.py` | 历史看板，非必需，别和 5173 搞混 |
| 9222 | Edge 调试端口 | 与本项目无关，是浏览器残留 |
