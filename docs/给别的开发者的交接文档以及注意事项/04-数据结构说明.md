# 04 · 数据结构说明

> 读者：接手代码的开发者。以下 schema 均为**实测**（直接解析磁盘上的文件得到）。

## 1. `web/public/data/local_pose_2min.json`

由 `api_teacher/run_local_pose.py` 生成，5 Hz。

```jsonc
{
  "video": "vedio\\v2_5m_7m_h264.mp4",   // 源视频（字符串，可能含反斜杠）
  "fps": 24.702,                          // 源视频帧率
  "duration": 119.99028418751517,         // 源视频时长（秒）
  "rate": 5.0,                            // 采样频率 Hz
  "pad": 0.1,                             // 人体框外扩比例
  "frames": [                             // 600 条，timestamp = 0, 0.2, ..., 119.8
    {
      "timestamp": 12.4,
      "person": {                         // 该帧没检测到人时为 null
        "bbox": [x0, y0, x1, y1],         // 原视频像素坐标
        "score": 0.87
      },
      "left_hand":  [[x, y, score], ...], // 21 点，原视频像素坐标
      "right_hand": [[x, y, score], ...]  // 21 点
    }
  ]
}
```

要点：

- **坐标已是原视频像素坐标**（`decode()` 扣掉了 letterbox 的 `left/top` 再除 `scale`）。
  改这里之前务必读 `05-踩坑与注意事项.md` 第 1 条。
- `left_hand` / `right_hand` 在以下情况是**空数组 `[]`**（不是 21 个 null）：
  - 该帧没检测到人；
  - 有效点（`score > 0.18`）不足 4 个；
  - 被 `keep_hand()` 判为假检测（21 点几乎重合，或整只手贴画面边缘）。
  所以前端判断"有没有手"必须写成 `(pts || []).filter(p => p[2] > 0.18).length >= 4`，
  不能直接 `pts.length === 21`。
- 21 点的顺序是 MediaPipe 手部约定（腕点 0，四指各 4 点）。
- **新增可选字段 `left_box` / `right_box`**（由 `extract_roi.py --write-boxes` 写入）：
  原视频像素坐标 `[x0,y0,x1,y1]`，用于前端在画面上画手框。未识别时为 `null`。
  顶层还会写一个 `hand_box` 元信息：`{size, roi_pad, display_pad, score_thr, min_points, max_side_ratio}`。
  注意**显示框用 `display_pad=0.10`（贴合手），ROI 裁图用 `roi_pad=0.40`（要带进手里的工具）**，两者不同。

**实测覆盖（600 帧，启用掌骨一致性过滤后）**：`person` 有效 520、左手有效 452、右手有效 413。

## 1.1 `web/public/data/segments.json`（前端唯一认的工序数据）

由 `scripts/build_segments.py` 生成，**统一到单一时间基准**（`duration` = 视频时长）：

```jsonc
{
  "version": 1,
  "video": "v2_5m_7m_pose.mp4",
  "duration": 119.99,
  "source": "ablation",                       // 数据来源，将来 teacher 也一样
  "note": "来自 ablation_14_A（固定 3 秒窗口，仅覆盖前 30 秒）",
  "coverage": [0.0, 30.0],                    // ⚠️ 这份数据实际只覆盖到这里
  "steps": [
    { "idx": 0, "step_id": "W00", "name": "装配 · 黑色塑料壳体（疑似车灯组件）",
      "start": 0.0, "end": 3.0, "kind": "step", "source": "ablation", "color": 0 }
  ]
}
```

- 相邻且 `name` 完全相同的段会被合并（`merged` 字段记录合并了几段）。
- 前端把 `coverage` 之外的区域当作"无数据"，卡片会显示提示，不会拿第一段冒充当前段。
- 以后教师模型跑全片，只需重新生成这个文件，`App.vue` 不用改。

### 手部识别片段怎么算（`App.vue` 的 `buildSegments`）

```js
HAND_SCORE = 0.18   HAND_MIN_POINTS = 4   HAND_MERGE_GAP = 0.35
```
与 `render_pose_video.py` 的 `SCORE_THR`、`run_local_pose.py` 的 `score_thr` 必须一致，
否则「视频里的骨架」「进度条」和「手框」三者会对不上。

## 2. `web/public/data/ablation_14_{A,B,C}.json`

由 `api_teacher/run_ablation.py` 生成。三个文件结构相同，
**每个文件只有自己那组有内容，另外两组是空数组**：

```jsonc
// ablation_14_A.json
{ "A": [ ...10 条... ], "B": [], "C": [] }
// ablation_14_B.json
{ "A": [], "B": [ ...10 条... ], "C": [] }
// ablation_14_C.json
{ "A": [], "B": [], "C": [ ...10 条... ] }
```

每条：

```jsonc
{
  "start": 0,          // 窗口起点（秒）
  "end": 3.0,          // 窗口终点（秒），固定 3 秒
  "evidence": {},      // 该组喂给模型的结构化证据，见下
  "response": "{\n  \"action\": ... }",   // ⚠️ 字符串形式的 JSON，需二次 JSON.parse
  "frame_paths": ["api_runs\\ablation_14_A\\frames\\frame_0000_00.jpg", ...]
}
```

`evidence` 三组差异：

| 组 | evidence 内容 |
|---|---|
| A | `{}`（空） |
| B | `{"frames": 30, "person_frames": 30, "person_present": true}` |
| C | `{"frames": 30, "person_frames": 30, "hand_detections": 60, "left_wrist": [x,y,score], "right_wrist": [x,y,score], "hand_keypoints_available": true}` |

`response` 解析后的字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `action` | 当前动作 | `screwing` / `使用电动螺丝刀拧入螺丝` |
| `phase` | 动作阶段 | `tightening_screw` / `装配` |
| `left_hand` | 左手在做什么/拿什么 | `holding_black_plastic_housing` |
| `right_hand` | 右手在做什么/拿什么 | `operating_electric_screwdriver` |
| `tool` | 工具 | `electric_screwdriver_with_orange_handle` |
| `object` | 工件/目标 | `black_plastic_housing` |
| `relation` | 手-工具-工件的组合关系 | `right_hand_operates_tool_on_object; left_hand_stabilizes_object` |
| `change` | 相比上一窗口的变化 | `screw_inserted_into_housing` |
| `unknown` | 无法确认的内容 | `""` |

> ⚠️ **已知不一致**：A 组输出中文，B/C 组输出英文（同一提示词、temperature 0.1 下的抖动）。
> 前端直接展示，所以卡片会中英混排。若要统一，需在提示词里强制语言或加后处理。

## 3. 时间基准（最容易搞错）

| 数据 | 覆盖范围 | 采样 |
|---|---|---|
| `v2_5m_7m_pose.mp4` | 0 – 119.99 s | 24.7 fps |
| `local_pose_2min.json` | 0 – 119.8 s | 5 Hz |
| `ablation_14_*.json` | **仅 0 – 30 s** | 10 个 3 s 窗口 |

所以底部两条轨道**不是同一坐标尺度**：

- 「工序」轨道 = `ablation_14_*.json` 的 10 个窗口 → 映射到 0–30 s
- 「左右手识别片段」条 = `local_pose_2min.json` → 映射到 0–119.99 s

前端用 `poseDuration`（=120）做统一分母，因此「工序」轨道实际上是 0–30 s 的内容
被**等宽铺满整条 120 s 轨道**，属于占位显示。页面上已加小字说明。
这是下一阶段"不等长 SOP 片段"要解决的第一个问题。

## 4. 前端如何切"左右手识别片段"

`App.vue` 的 `buildSegments(rows, key)`，口径必须与烧录视频一致：

```js
HAND_SCORE = 0.18        // 单点阈值
HAND_MIN_POINTS = 4      // 至少 4 个有效点才算识别到
HAND_MERGE_GAP = 0.35    // 相邻段间隔 ≤0.35s 就合并，避免单帧漏检切碎
half = 1 / (2 * rate)    // 每帧向两侧各扩 half 秒
```

改阈值时 **`render_pose_video.py` 的 `SCORE_THR` 与这里的 `HAND_SCORE` 必须同步**。

## 5. 紧固件计数输入（`scripts/count_fasteners.py`）

每行/每行的 CSV 字段（都可省略，有默认值）：

```jsonc
{"timestamp": 12.4, "placement": 0.9, "tool": 0.88, "release": 0.1, "visible": true}
```

输出：

```jsonc
{
  "count": 3,
  "state": "complete",
  "events": [{"event_id":1, "start_timestamp":.., "end_timestamp":.., "state":"complete",
              "placement_score":.., "tool_score":.., "repeated_presses":2, "confidence":..}],
  "timeline": [{"timestamp":.., "state":"fastening", "count":1, ...}]
}
```
