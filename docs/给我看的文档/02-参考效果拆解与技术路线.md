```text
│  右手  ▓▓░░▓▓▓▓▓▓░░▓                                              │
└────────────────────────────────────────────────────────────────────┘
```

我观察到的几个**关键设计细节**（这些决定了工作量）：

1. **骨架是逐帧跟随的**，不是关键帧插值——说明它对每一帧都跑了姿态模型，或者至少用了高采样率 + 插值。
2. **左右手用两种颜色 + 手腕处 L/R 小字**，这是为了在画面里也能区分左右，不只是靠颜色。
3. **右手卡片是橙色主题**，和右手骨架颜色一致 → 视觉上把"画面里的手"和"右侧卡片"绑定了。
4. **三轨时间轴都带播放头**，且与视频联动 → 说明底层是统一时间基准的（不像我们 30s vs 120s 分裂）。
5. **卡片内容是"结构化字段"而不是一段自由文本**：标准SOP / 当前动作 / 左手 / 右手 各占一格，说明后端有一个**固定 schema**，不是让模型随便写。

## 四、"标准 SOP 描述"是人工写的还是 AI 生成的？

**我的判断：高概率是人工固定（或 AI 起草 + 人工冻结）的查表结果，不是每个窗口现场生成的。**

理由：

1. **标题语义**："标准 SOP 描述" 与 "当前动作描述" 并列出现 —— 这是标准的
   **"应有" vs "实际"** 对照结构。如果两者都是 AI 生成，没必要分成两张卡。
2. **措辞稳定性**：同一段视频里 SOP 描述反复出现同一批措辞，更像查表命中而不是每次重新生成。
3. **工业常识**：SOP 本身就是工艺文件，是"应该怎么做"的定义，天然由人给出。
4. **我们项目自己的结论**：仓库 README 里也写着"后续开发顺序应是**先固定 SOP 配置**，
   再接入手部和工具检测证据"——这和参考实现的做法一致。

**但我不建议你手工从头写。** 更省事且更可靠的做法是：

```text
① 用 Qwen-VL 把整段视频按粗窗口过一遍 → 让它"自由命名"出现过的动作
② 人工合并同义项、排序、补上目标物 → 得到 8~10 步的 SOP 草表
③ 人工审核冻结成配置（sop_steps.json / yaml）
④ 正式跑的时候，提示词改成"从下列步骤中选择最匹配的一个"，禁止自由发挥
```

这样 SOP 表既贴近真实工艺，又不至于纯靠拍脑袋。**第①②步我可以直接做，③需要你审核。**

> ✅ **补充证据（2026-11-14 二次分析）**：虽然当前模型 `read_image` 报错不支持图像输入，
> 但用 **Windows 本地 OCR** 成功提取了你截图里的 11 条「标准 SOP 描述」，
> 完整文字与错字修正见 [`05-参考视频SOP描述OCR记录.md`](05-参考视频SOP描述OCR记录.md)。
> 结论因此升级为：**有文字证据支持"人工固定/人工冻结的查表结果"**——
> 因为里面存在「流程外或插入式局部处理」「循环外停留与准备」这类人工设计的兜底类别，
> 且有 1 条完全重复（同一工序循环多次时显示同一句），模板化句式贯穿全部 11 条。

> 照抄前必须先确认是否同一工位，详见 `05` 第五节。

## 五、"教师模型 → 学生模型"这条路怎么理解

这是**知识蒸馏（Knowledge Distillation）**在工程上的一种用法，不是学术意义的严格蒸馏。

```text
                       ┌──────────────────────────────────┐
   离线 / 云端 / 有 GPU   │  教师模型：Qwen-VL（或 GPT-4o）    │
                       │  · 看得懂画面语义                  │
                       │  · 能输出结构化描述                 │
                       │  · 但：慢、贵、要联网、不能上 NX      │
                       └───────────────┬──────────────────┘
                                       │ 逐窗口结构化标签
                                       ▼
                       ┌──────────────────────────────────┐
                       │  标签化数据集                       │
                       │  · 窗口 → {步骤, 左手, 右手, ...}   │
                       │  · 对齐到 BORIS 人工标注做校验       │
                       └───────────────┬──────────────────┘
                                       │ 训练
                                       ▼
                       ┌──────────────────────────────────┐
                       │  学生模型：轻量、本地、实时          │
                       │  · 路线1：骨架/几何特征 + TCN       │
                       │  · 路线2：RGB 3D-CNN（R3D-18）     │
                       │  · 量化 + TensorRT → Jetson NX     │
                       └──────────────────────────────────┘
```

**为什么值得这么干：**

| | 教师（VLM） | 学生（本地） |
|---|---|---|
| 速度 | 一次调用秒级，整片几百次 | 每帧毫秒级 |
| 成本 | 按调用计费 | 一次性算力 |
| 部署 | 必须联网/GPU | NX 可跑 |
| 精度 | 语义最强 | 取决于特征和标签质量 |

**这条路成立的关键前提（也是最大的风险）：**

1. **教师标签必须"时序一致"**。VLM 每个窗口独立判断，相邻窗口可能自相矛盾（同一个动作被判成两步）。
   不处理就直接当训练标签，学生会学到噪声。→ 必须有合并/平滑/最短时长约束。
2. **教师标签要有真值校验**。你们已有 BORIS 人工标注
   （`project/data/evnets/*.csv`，目前出现过的行为标签是 `install_screw`、`use_screwdriver`），
   这就是现成的真值集，**教师输出必须先在它上面算一遍准确率**，再拿去训学生。
3. **学生看到的信息必须比教师少**，但要有足够区分度。只用骨架坐标往往分不清
   "取得黑色壳片"和"取得银灰带筋件"（轨迹相似、物体不同）—— 这就是为什么要有**手部 ROI 小图**这条路。

## 六、我建议的推进顺序（每步都有可验收产物）

### P0 · SOP 表 + 提示词定稿（1~2 天，几乎零成本）

- 产出 `sop_steps.json`：8~10 步，每步含 `step_id`、中文名、涉及的手、目标物、预期时长。
- 产出定稿提示词：中文输出、字段固定、**只允许从 SOP 表里选**。
- 验收：把 30 s 试点重跑一遍，卡片内容明显比现在规整。

### P1 · 教师跑通全片 + 时间轴统一（2~3 天，有 API 费用）

- 全片跑 Qwen-VL（建议先 stride 3 s 试 120 s，成本可控后再上全片）。
- 新增 `segments.json`：不等长片段（合并相邻同 step 窗口），**统一 0–120 s 时间基准**。
- 页面三轨（工序/左手/右手）全部基于同一份 `segments.json`。
- 验收：播放时三轨播放头对齐；每段能点；卡片与段一致。

### P2 · 左右手语义升级（这是差距最大的一步）

- 加工具/工件检测 → 手-物关联 → 左右手卡片输出"右手：操作电动螺丝刀 / 接触螺丝"
- 片段条从"有没有手"升级为"左手做了什么 / 右手做了什么"。
- 验收：能看出"左手扶、右手拧"这类组合，而不是两条几乎重合的条。

### P3 · 学生模型 + NX（依赖 P1/P2 的数据）

- 用教师标签 + BORIS 真值训练；先在独立录像上验证泛化；
- 量化 → TensorRT → NX 实测帧率与内存。

**我的建议：先做 P0，再做 P1。** 不要在 SOP 表没定的情况下继续堆 UI 和提示词——
那是现在 30 s 试点产出"中英混排、时间基准分裂"的根本原因。

## 七、与参考效果的差距清单（按影响排序）

| # | 差距 | 影响 | 难度 |
|---|---|---|---|
| 1 | 没有固定 SOP 步骤表 | 卡片内容不可控、无法验收 | 低（人工定） |
| 2 | 时间基准分裂（30 s vs 120 s） | 三轨无法真正对齐 | 低 |
| 3 | 左右手语义只有"有没有手" | 与目标效果差距最大 | 中（要手-物关联） |
| 4 | 片段是固定 3 s 等宽 | 参考视频是不等长片段 | 中 |
| 5 | 语言中英混排 | 观感差 | 极低（改提示词） |
| 6 | 无跟踪、无时序平滑 | 抖动、ID 跳 | 中 |
| 7 | 人体框还在画面上（已是淡虚线） | 参考视频里也有框，可接受 | 低 |
