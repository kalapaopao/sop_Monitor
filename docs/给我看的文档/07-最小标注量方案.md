# 07 · 最小标注量方案（MVP-0）

> 读者：项目负责人。
> 起因：负责人指出「为了识别还要标人/手/工具/工件框，那我用别的方案更省事；
> 我要的是大模型帮我减标注，还要能傻瓜式换产线」。这条**成立**，
> 本文替代 `06` 里"必须做物体检测"的说法。

## 一、结论先说

**首版不训练任何检测模型，不标任何物体框、不标手框。**
只保留两种已有能力（person 检测 + RTMW 手部关键点），加上一个**零标注**的动作：
把手的周围裁成小图喂给模型。人工只标一样东西：**SOP 段落**（BORIS）。

```text
人工标注量对比（1 段 120 s 视频）
─────────────────────────────────────────────
方案 A（初版 06，我撤回的）：
  人框 ✅ 已有   手框 120 帧级   工具框 120 帧级   工件框 120 帧级   SOP 段 40 段
  → 逐帧框标注 ≈ 数千个框

方案 B（本文）： 
  人框 ✅ 已有   手框 ❌ 由关键点算出   工具/工件框 ❌ 由 ROI 裁图替代
  SOP 段 40 段（且可被教师预填，人工只改错 → 实际 ≈ 10~15 段的工作量）
  → 框标注 = 0
```

## 二、为什么"裁图"能替代"标框"

这是整个方案的关键，值得讲清楚：

| | 标框方案 | ROI 裁图方案 |
|---|---|---|
| 谁提供物体信息 | 人画的框 + 框的类别 | **像素本身** |
| 换产线要做什么 | 重新标所有物体的框 | 什么都不用标 |
| 模型怎么知道"手里是黑色壳片还是银灰带筋件" | 看检测框的类别标签 | 看小图里那块颜色的形状（CNN 自己学） |
| 代价 | 人力 | 一点算力（96×96 小图，约 2~5 ms） |

**直觉例子**：
「取得黑色壳片」和「取得银灰带筋件」——如果只看 21 个手部关键点，两个动作的
手腕轨迹几乎重合，**不可分**。但把手周围那块 96×96 的图裁出来，
一个是深色片状、一个是银灰色长条，CNN 一眼就能分开。
**人为这个"分开"付出的额外标注是 0。**

## 三、四条证据线（全部零人工标注）

| # | 证据 | 来源 | 标注成本 |
|---|---|---|---|
| E1 | 人体框 + 位置/大小/朝向 | YOLO（已有） | 0 |
| E2 | 左右手 21 点、速度、握合度、可见性 | RTMW（已有） | 0 |
| E3 | **左手 ROI 小图 / 右手 ROI 小图** | 由 21 点算最小外接框 + 外扩 30~50% → 裁 96×96 | **0** |
| E4 | 手与固定区域的关系（可选） | 人工在画面上"框一次"工位/夹具区域（一个矩形/机位） | 每个工位 1 次 |

> E4 是唯一要人点一下鼠标的动作，但它是**工位配置**，不是逐帧标注；
> 换产线时如果机位不变，可以完全复用。

### E3 已实现（2026-11-14）

`api_teacher/extract_roi.py`，只用姿态关键点算框裁图，**0 标注**。

实测（`v2_5m_7m_h264.mp4` 全片 600 帧）：

| 项 | 结果 |
|---|---|
| 裁图数 | 961 张（左手 459 / 右手 502，与姿态有效帧完全一致） |
| 耗时 | **4.2 秒**（顺序解码，非逐帧 seek） |
| 磁盘 | 3.2 MB（96×96 JPEG，平均 3 KB/张） |
| 框边长 | 中位数 129 px，范围 29–697 px |
| 手部凸包占框面积 | 中位数 0.21，p10 0.11，p90 0.35 |
| 近空白图 | 0 |

**踩到的坑（已修）**：直接用 21 点 min/max 会被个别"飞点"带偏，
首版最大框边长到 **963 px**（画面一半），手只占框面积 **12%**，等于裁了一大片背景。
改为 **中位数中心 + MAD 3σ 剔离群点**，并给框边长加上限（≤ 短边的 40%），
框边长中位数从 171 → 129 px，手占面积 0.12 → 0.21。

> 注意：0.21 不是"裁小了"，而是手指张开时凸包本来就细长；
> 外扩 40% 是为了把手里的工具/工件一起带进来，这个值可以调（`--pad`）。

## 四、唯一的人工标注：SOP 段（你已同意）

```text
cycle_id, step_id, start_ts, end_ts, annotator, note
```

- 每段一个 `step_id`（来自冻结的 SOP 表，含 S10/S11 兜底类）
- **教师预填**：先让 Qwen-VL 按窗口粗分一遍 → 人只改错的段
  → 实测经验值：人工工作量降到 20%~30%（**未验证，需要用你的第一批数据测**）

## 五、学生模型（MVP-0）

```text
输入
  E1+E2 → 骨架特征   [T=64, 50]        (躯干 8 点 + 双手各 21 点)
  E2    → 手部几何   [T=64, ~16]       (速度、开合、可见性、两腕距离)
  E3    → 左右手 ROI [T=64, 2, 576]    MobileNetV3-Small 共享权重，各前向一次

主干    拼接 → 2 层 TCN (kernel 3, hidden 128)
三头    step(12 类) / left_hold(粗类) / right_hold(粗类)
解码    HMM + SOP 转移约束 + 最短段 1.5 s（见 `06` L3）

规模    ~3 M 参数；ONNX 量化后 < 5 MB
```

`left_hold` / `right_hold` 这两个头**只用于辅助训练**（监督密度高），
推理时可以不做强约束。

## 六、算力实测（纯 CPU，未走 GPU）

本机（桌面 CPU）实测：

| 环节 | 耗时 |
|---|---|
| YOLO person 640×640 | 7.3 ms |
| RTMW 256×192（133 点） | 18.0 ms |
| 合计 | **25.6 ms / 帧** |
| + ROI CNN 96×96 ×2 | 约 +3~8 ms（按 MobileNetV3-Small 估，**未实测**） |
| + TCN 64×~250 | < 1 ms |

推算：

| 场景 | 每帧预算 | 占用 | 结论 |
|---|---|---|---|
| 单路 @10 Hz | 100 ms | 26% | 轻松 |
| 4 路 @5 Hz | — | 0.51 核秒/秒 | 1 核即可 |
| 4 路 @10 Hz | — | 1.02 核秒/秒 | 1~2 核 |
| 8 路 @5 Hz | — | 1.02 核秒/秒 | 2 核 |

**→ 算力不是瓶颈，不需要为了省算力砍掉手部模型。**
⚠️ 但以上是**桌面 CPU**，Jetson NX 通常慢 2~4 倍，**必须在 NX 上重测**（未验证）。
按 3 倍估算：4 路 @5 Hz ≈ 1.5 核秒/秒，仍在 6 核预算内。

## 七、这套方案怎么满足"傻瓜式换产线"

换一条产线，需要人做的只有：

1. **换 SOP 词表**（10 条文字，改一个 JSON）
2. （可选）在画面上框一次工位区域
3. **标 20~30 段 SOP**（教师预填 → 人工改错）
4. 点"训练"，看段级 F1 和混淆矩阵
5. 点"部署"，模型热替换

**不需要重标任何物体框、手框。** 这与你要做的辅助标注平台（`assisted_annotation_platform`）天然吻合。

## 八、什么时候才不得不回头做物体检测

诚实说明边界。只有出现下面情况之一，才需要退回"标一点框"：

| 情况 | 表现 | 对策（也不是全量标） |
|---|---|---|
| 两个步骤手里的东西**外观也几乎一样** | ROI 图分不开，混淆矩阵里两类互错 | 给这**两类**各标 30~50 个框，做小检测器 |
| 物体被手**完全遮住**，只有放下后才看得见 | ROI 里全是手 | 增加"放下后"的工件区 ROI，或加一个固定区域检测 |
| 手长时间离开画面 | 无 ROI | 用 E4 的工位区域兜底 |

**这是升级路径，不是起点。** 先把零标注方案跑出基线，再看缺什么补什么。

## 九、和参考实现的一致性

参考视频里也没有看到"工具框/工件框"——它画的是 person 框 + 左右手骨架 + 手腕标签。
SOP 卡写的是物体状态（文字），不是检测框。
→ **说明它同样是"骨架 + 语义模型"路线，没有做物体检测。** 这从侧面支持本方案。
