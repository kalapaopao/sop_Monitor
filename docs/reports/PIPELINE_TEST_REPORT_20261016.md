# 07 视频：C++ 多线程流水线实测（2026-10-16）

## 结论与范围

已实现可选的解码/推理/显示流水线，以及 OBB 与 YOLOX→RTMW 两条分支并发。原串行路径保留为默认 `legacy`，三个模型、FP16 引擎、阈值、裁剪和关键点解码没有改变。

在同批帧、同样逐帧推理条件下，并发模式无窗口预热后约 27.1–27.4 FPS；带窗口约 24.65 FPS。独立时钟播放模式约 25 FPS，但会跳过尚未开始的推理任务，不能称作每帧全部识别。

本轮没有实现硬件解码、CUDA 图像预处理、人体跟踪、运动补偿、关键点平滑、DLA 或模型替换；没有安装依赖、改变功耗模式、提交或推送代码。

## 测试条件

- 设备：当前 Jetson Orin NX；系统可见内存约 6848 MB。
- 软件：已有 JetPack 5.1.1 / TensorRT 8.5.2 / OpenCV 4.5.4 / CMake 3.16.3。
- nvpmodel 报告 MODE_20W_6CORE；部分功耗参数读取报权限错误，未修改系统配置。
- 输入：`../test_vedio/07.mp4`，1920×1080，约 25 FPS，14978 帧。
- 固定帧测试从 180 秒开始，读取完全相同的 330 帧；前 30 帧预热，后 300 帧统计吞吐量。
- 三模型逐帧条件用正序、反序各跑一次；2/2/3 条件每种模式跑一次。
- 无窗口测试不绘制画面、不录制，三种测量模式工作量一致。因此不能将其数字直接和旧 legacy 的 headless 日志横向比较。
- 实时显示测试同样从 180 秒开始，解码 450 帧；前 75 个实际显示帧用于预热。
- 日志和逐帧 CSV：`output/pipeline_07_20261016/`，资产哈希见 `assets.sha256`。

## 固定帧、无窗口结果

| 模式 | OBB/人体框/姿态间隔 | 预热后 FPS | 帧消费间隔 P95（ms） |
|---|---|---:|---:|
| serial 第 1 轮 | 1/1/1 | 18.028 | 61.614 |
| pipeline 第 1 轮 | 1/1/1 | 21.051 | 49.073 |
| parallel 第 1 轮 | 1/1/1 | 27.061 | 38.655 |
| parallel 第 2 轮 | 1/1/1 | 27.381 | 38.204 |
| pipeline 第 2 轮 | 1/1/1 | 23.124 | 44.344 |

| serial | 2/2/3 | 32.640 | 57.459 |
| pipeline | 2/2/3 | 46.745 | 47.094 |
| parallel | 2/2/3 | 60.854 | 38.113 |

每组均 decoded=inferred=displayed=330，丢弃计数为 0。1/1/1 条件每组 OBB 调用 330 次、YOLOX 调用 330 次、RTMW 人体裁剪调用 332 次（少数帧检出多个人体）；2/2/3 条件分别为 165、165、110 次。

60.854 FPS 是复用部分旧结果的吞吐量，不是三个模型各自每秒产生 60.854 次新识别。第一轮和第二轮的差异说明仍存在时钟、负载等波动，数据不足以给出绝对性能上限。

## 窗口显示结果

| 模式 | 规则 | 显示 FPS | 显示间隔 P95（ms） | 应用读帧到绘制前 P95（ms） |
|---|---|---:|---:|---:|
| serial | 330 帧全部识别，1/1/1 | 14.339 | 73.442 | 57.273 |
| parallel | 330 帧全部识别，1/1/1 | 24.646 | 53.723 | 184.686 |
| pipeline 实时 | 按时间轴显示，推理取最新待处理帧 | 24.661 | 66.332 | 35.021 |
| parallel 实时 | 按时间轴显示，推理取最新待处理帧 | 25.000 | 52.584 | 22.814 |

固定帧并发比固定帧串行的显示吞吐量提升约 72%。固定帧模式会等待匹配结果，解码队列和结果队列均有界，额外排队会增加应用内延迟；它不能同时保证固定 25 FPS 和最低延迟。

parallel 实时模式：

- 解码 450 帧、显示 448 帧、实际处理 381 个推理任务。
- 68 个未开始的推理任务被更新帧替换，2 个预览帧被替换；这不是将这些帧成功识别了。
- 包含启动阶段的任务率 21.179 次/秒；从 CSV 去掉前 75 个显示帧后，任务更新率约 23.39 次/秒，RTMW 人体裁剪约 23.46 次/秒。
- 骨架源时间年龄 P95 约 120 ms，检查未发现未来帧结果绘制到过去帧。
- 默认采用可配置的 200 ms 显示过期阈值（`--max-result-age-ms`），超过后隐藏结果；这不是业务准确率阈值。
- 首次推理会有 CUDA 初始化开销，视频启动后可能短暂没有骨架。

显示指标测量应用准备绘制的时间点，不含 GTK 实际呈现、VNC/xrdp 传输或 Windows 客户端呈现，不能等同于远程屏幕帧率。

## 正确性与异常测试

- 所有 9 组无窗口结果，每组 330 帧的帧编号和识别结果指纹均与对应 serial 基线一致；0 个不匹配。
- 两组同帧 GUI 测试也各有 330 帧指纹与逐帧基线一致。
- 指纹包含检测类别、置信度、框顶点及选中人体的框、关键点和分数。它验证执行结果一致性，不是人工标注准确率或严格逐元素误差评估。
- `pipeline_queue` 测试通过：10000 项 FIFO、有界背压、关闭后排空、取消唤醒、最新任务替换。
- 构建成功。保留原 TensorRT binding API 的 deprecated 警告。
- 第一次使用 `ctest --test-dir` 因设备 CMake 3.16.3 不支持该方式而未找到测试；改用 `(cd build && ctest --output-on-failure)` 后实际通过。
- 并发分支故意传入不兼容姿态引擎，出现预期的 setBindingDimensions 错误，以退出码 1 结束，没有触发 25 秒超时；原模型文件未修改。
- 非法 mode 和负数帧数均被拒绝，以退出码 1 结束。
- 旧启动命令不带 mode、无窗口短时运行成功。该测试受首次 CUDA 初始化支配，不用于性能比较。
- GTK 提示缺少 canberra 模块，测试仍完成；没有执行系统软件安装。
- git diff --check 通过。

## 使用与回退

推荐先观察新的实时模式，所有间隔保持 1，让每个选中的推理任务都产生新结果：

```bash
cd /home/nvidia/Music/project/sop_Monitor
./build/sop_nx_infer --source ../test_vedio/07.mp4 --model-dir models \
  --mode parallel --realtime --start-sec 180
```

点击窗口后按 q 或 Esc 退出。要保留每帧完整识别、接受处理速度变化，则去掉 `--realtime`。要恢复原串行行为，使用 `--mode legacy` 或不带 mode；旧 stride 参数继续有效。

NX 修改前源码、CMake、README 和可执行文件备份位于 `/tmp/sop-pipeline-before.nFukKe/`，该临时目录重启后可能被清理。需要文件级回退时先停止程序，再将这些备份分别复制回 `src/main.cpp`、`CMakeLists.txt`、`README.md` 和 `build/sop_nx_infer`；本轮新增头文件、测试和脚本可先保留，它们不会被旧 CMake 引用。根目录 .gitignore 仅增加了 `Testing/` 规则，可单独撤销该行。
