# docs 目录说明

本目录是 `sop_offline_teacher` 的文档区，按**读者**分成两个子目录，不要混写。

```text
docs/
├── README.md                                  ← 你在看的这页（索引 + 约定）
├── 给别的开发者的交接文档以及注意事项/            ← 面向接手代码的人：怎么跑、数据结构、坑
└── 给我看的文档/                                ← 面向项目负责人：现状、决策、路线、待拍板事项
```

## 分工原则

| 目录 | 读者 | 内容特征 |
|---|---|---|
| `给别的开发者的交接文档以及注意事项/` | 接手/协作开发的人 | 全部是可从代码与命令验证的事实：架构、目录、运行命令、数据结构、踩坑记录。**不含未经证实的判断。** |
| `给我看的文档/` | 项目负责人（你） | 现状结论、方案取舍、风险、待决策项、验收清单。允许出现"建议/推荐/未验证"等判断性表述，但必须标清可信度。 |

## 硬约定

1. **文档里的路径、命令、参数必须实际跑过**。没验证的写成"未验证"。
2. 改代码后同步改文档，尤其是：
   - `run_local_pose.py` 的坐标逻辑 → 改 `04-数据结构说明.md` 与 `05-踩坑与注意事项.md`
   - `App.vue` 的数据源 / 时间轴口径 → 改 `04-数据结构说明.md`
3. 大文件（视频、onnx、api_runs）不入库，文档里写清"怎么生成"，不要贴二进制。
4. 凭据永远不写进文档，只写环境变量名。

## 快速导航

- 想跑起来 → `给别的开发者的交接文档以及注意事项/03-本地运行手册.md`
- 想搞懂数据格式 → `给别的开发者的交接文档以及注意事项/04-数据结构说明.md`
- 想避免重复踩坑 → `给别的开发者的交接文档以及注意事项/05-踩坑与注意事项.md`
- 想知道项目处于什么状态、下一步做什么 → `给我看的文档/01-项目现状与决策记录.md`
- 想知道目标效果怎么拆、技术路线怎么选 → `给我看的文档/02-参考效果拆解与技术路线.md`
- 想核对教师提示词与 SOP 表 → `给我看的文档/03-教师模型提示词与SOP标准描述.md`
- 想看**从参考视频截图里 OCR 出来的真实 SOP 文字** → `给我看的文档/05-参考视频SOP描述OCR记录.md`
- 想知道**识别模型该怎么设计**（分层、学生模型结构、评估） → `给我看的文档/06-识别模型设计方案.md`
- **只想看"最少要标什么"**（不标框、只标 SOP 段、算力实测） → `给我看的文档/07-最小标注量方案.md`
- 要**画固定 ROI / 理解关注但不裁剪怎么实现** → 给我看的文档/09-固定ROI注意力设计.md
- **要给领导/非技术同事汇报**（一段话讲清做什么、到哪了、要什么支持） → `给我看的文档/08-项目汇报给领导.md`
